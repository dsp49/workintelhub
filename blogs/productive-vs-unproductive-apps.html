Productive vs Unproductive Apps: How Classification Works

P Pavan
November 26, 2026 · 8 min read

Productivity monitoring software decides whether an app is productive by looking it up in a list your company maintains, usually per team or role, that labels each application and website productive, unproductive or neutral. The agent then totals your active time in each label, and that total becomes your productivity score.

The label is not a property of the app. Slack is work for a support agent and a distraction for a developer in a focus block; YouTube is a time sink for most people and the job for a video editor. This page explains how classification works, how the major tools set it up, where it goes wrong, and how to build lists people will accept. The demo lets you watch one app change label as the role changes.

The short answer

A label is a lookup, not a judgment. The agent records the app or site in the foreground and checks it against a list someone at your company configured.

Labels are per role. The same app is productive for one team, neutral for another and unproductive for a third.

Unlabeled apps are the hidden problem. Anything not on the list lands as neutral or undefined, and the score quietly ignores it.

How classification works

Every tool in our productivity monitoring software comparison builds its score from three inputs: which application or site was in the foreground, whether the person was active (keyboard or mouse input within a timeout), and how that application is classified for the role. Classification is the third input and the one an employer controls completely.

  1. Capture. The agent logs the foreground application name and, for browsers, the site or URL, with the time spent in each.
  2. Active filter. Time with no input past the idle threshold is set aside as idle or passive.
  3. Lookup. The app or domain is matched against the classification list for the person's team or role.
  4. Totals. Active time is summed into productive, unproductive and neutral (or undefined) buckets, which feed the score, utilization or trend report.

Note what is not in the lookup: what you did inside the app. An hour in a spreadsheet is productive whether you built the budget or stared at one cell. That is why classification measures time in approved tools, which is a proxy for productivity, not productivity itself.

Where classification goes wrong

  • The browser problem. Most work now happens in a browser, so a list that labels the browser itself tells you nothing. Classification has to happen at the site level, and every new internal tool, client portal or documentation site starts unlabeled.
  • One list for everyone. Writing code in an IDE is productive for an engineer and undefined for a salesperson. A company-wide list either punishes specialists or labels so much as neutral that the score means little.
  • Work the agent cannot see. Meetings with no typing, phone calls, whiteboards and thinking fall out as idle before classification is applied. Most tools treat a meeting as idle; ActivTrak's offline meeting time and calendar integrations are the exception noted in our comparison.
  • The neutral bucket. Neutral time is usually excluded from the score, so a person who spends the morning in an unlabeled client tool can score higher or lower depending only on what the denominator includes. Our page on how an employee productivity score is calculated works through that arithmetic.
  • Gaming. Every method is gameable in proportion to how directly it is rewarded. Classification produces work done in the approved application, a cousin of the mouse jiggler that activity scores produce.

If your app is labeled wrong

Employees usually see the result of classification before they see the list. A morning in a client portal shows up as neutral, or a research site you need shows up as unproductive, and the daily score drops for reasons that have nothing to do with the work. Three steps fix most of it.

  • Open your own view. Most tools show tracked employees their own time by label. Find the specific apps and sites behind the neutral and unproductive totals.
  • Ask how your team's list is set up. Lists are set per team, so the fix is usually a one-line change by an administrator, not an exception for you.
  • Bring the job description. If a tool is part of the work, say which tasks use it. A label that contradicts the role is a configuration error, and reasonable managers treat it that way.

For what else the same agent records, see what Hubstaff can see and what Time Doctor can see; Time Doctor's own employee-facing advice, as our page puts it, is that the rating is only as good as the list.

How to build a list people will accept

  1. Start per team, not per company. Ask each team lead for the ten tools their people live in, and label those productive first.
  2. Leave the rest neutral. Mark something unproductive only when the whole team agrees it is off-task. An unfair unproductive label does more damage than a missing productive one.
  3. Review with the team. Show people the list and their own data. Every tool in our ranking except Teramind, Controlio and WorkTime has an employee self-view.
  4. Watch the neutral total. If neutral time is large, the list is incomplete. Review the top unlabeled sites monthly.
  5. Re-check after tool changes. A new CRM or design tool starts unlabeled and quietly lowers scores until someone adds it.
  6. Write it into policy. Say what the labels are used for and what they will not be used for. The productivity tracking policy covers the wording.

Classification measures time in tools, which is closer to a measure of input than output; the activity level percentage sits even further toward input. Key takeaways

  • Classification is a lookup: the agent records the app or site in the foreground and checks it against a list your employer configured.
  • Labels are per role or team; the same app can be productive, neutral or unproductive depending on who uses it.
  • Only active time is classified, so calls and meetings with no typing usually drop out as idle first.
  • Browsers must be classified by site, and unlisted sites land in a neutral or undefined bucket most scores ignore.
  • ActivTrak, DeskTime, Time Doctor, Monitask, Insightful, WorkTime and Time Champ all classify; RescueTime categorizes automatically for the individual.
  • Build lists per team, default to neutral, review them with employees, and watch the neutral total.

Frequently asked questions

How does software decide if an app is productive?

It looks the app or website up in a classification list your employer maintains, usually per team or role, and labels it productive, unproductive or neutral. It does not judge what you did inside the app.

Can the same app be productive and unproductive?

Yes. Lists are set per role or team, so a code editor can be productive for engineers and neutral for sales, and YouTube can be unproductive for most staff and productive for a video or social media team.

What does neutral or undefined mean?

Neutral or undefined time is time in an app or site the list has not labeled, or has deliberately left out. Most scores exclude it, so a large neutral total usually means the list is incomplete.

Is a browser productive or unproductive?

Neither by itself. Tools that work well classify browser time by site or URL. A browser-level label tells a manager almost nothing.

Can I see how my apps are classified?

Usually. Most productivity tools offer an employee self-view showing your own time by label. If a tool you need is marked unproductive, ask how your team's list is set up.

Who sets the productive and unproductive lists?

An administrator at your company, often with team leads. Vendors ship default categories in some tools, but the employer decides the final labels for each team.
